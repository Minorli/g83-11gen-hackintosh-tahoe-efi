# G83 本机维护路线

## 长期上游跟踪与部署约定（2026-11-16）

维护者要求持续优化本机。每次相关维护先检查以下上游自上次核对以来的提交、发行和
相关回归，先整合到自己的两个`main`，完成校验，再按具体授权部署本机。
本约定不创建后台定时更新，也不自动升级EFI。

| 自有维护线 | 主要上游 | 职责 |
| --- | --- | --- |
| Minorli/g83-11gen-hackintosh-tahoe-efi | xiananliu/g83-11gen-hackintosh-tahoe-efi | 完整脱敏EFI、硬件集成与本机验收 |
| Minorli/WhateverXe-Next | b00t0x/WhateverXe | 显卡源码、独立插件、故障证据和构建 |

同时核对xiananliu/wex-modified-edition与b00t0x/WhateverXe-Graphics。
闭源下游的HDMI/背光增强不能被假设包含于纯上游源码；发布更新不等于本机可直接替换。

1. 读当前部署记录，保留工作树；干净时`git pull --ff-only`，记录上游起止commit与核对日期。
2. 按问题合并必要变化，保留企业Wi-Fi修订、本机ACPI/USB、显示增强与来源许可。
   配置用匹配版本ocvalidate、引用及依赖检查；源码变化用相关测试与构建验证。
3. 提交并同步两仓库，保存组件SHA和互相引用的准确commit；候选、已落盘、启动生效、
   长期验收分开记录。没有更新或决定不合入时也记录具体依据。
4. 新实验安装前列出具体差异、回退入口与验收条件并取得明确同意；核对EFI分区身份，
   先备份私人配置、保留三码与ROM。由维护者决定重启时机，一次只改变一个可解释变量。
5. 启动后核对实际加载SHA和插件状态，再做有界负载验收；异常回退并更新记录。
   不杀WindowServer、不自动恢复VA、不改有意的镜像布局，不主动复现整机卡死。

根EFI当前为[本机快照](Current-EFI.md)，S0ix另存未部署候选。
WhateverXe-Next仅镜像脱敏config和完整文件指纹，完整EFI以本仓库为准。
私人身份、原始寄存器/反汇编、日志及Apple系统二进制不公开。
本机私有记忆入口是Projects下的`MAINTENANCE.md`，后续维护完成后同时更新。

## 历史巡检与后续验收

以下保留2026-11-12起的巡检脱敏结论。当前组件以本机快照为准；原始EFI、硬件身份、
认证信息与日志不进入仓库。0.4.3 Metal已改善内存增长，长期生命周期仍待验收。

不以“缺少某个 kext”为由盲装存储或电源组件。

## 分支与集成规则

- `main`：本机主维护线路，合入已明确边界的配置和文档改进。
- `fix/tahoe-enterprise-wifi`：独立无线贡献分支；不混入图形或整机设置。
- `fix/opencore-config-validation`：可供上游审查的配置结构校验及 I2C 依赖顺序修订。
- 图形源码：独立 WhateverXe-Next 项目。通过审查和实际验收后才集成其二进制。

仓库的公开配置是去身份的集成模板，不是私人启动配置的逐字副本。
每次部署前记录实际差异；格式校验、构建成功、单进程 GPU 测试、整机启动和长期验收分层记录。
保留工作软件、同步、远程工具及有意的镜像布局，不通过批量禁用服务掩盖图形问题。
